# 爬虫按小节获取题目 - 策略说明

## 一、变更背景

原策略通过 `has-progress` + `assembly` + `chapter/questions` 按整章获取题目，再根据题号与 `all_question_num` 推算归属小节。现改为**以 chapter/list 为唯一来源固定章和节，再按小节调用 section-questions 抓取题目**，数据更准确，避免小节遗漏。

## 二、章与节来源

**唯一来源**：`POST https://t.51cto.com/napi/chapter/list/sub-240`，payload `{"subject":"240"}`。

- 支持嵌套结构（`data.list` 中每项含 `child` 或 `children`）
- 支持扁平结构（`pid=0` 为章，`pid=章id` 为节），自动构建树
- 小节提取时同时兼容 `child`、`children` 字段，去重后按 `sort`、`id` 排序

## 三、section-questions 接口

```
GET https://t.51cto.com/napi/chapter/section-questions?id={小节ID}&user_subject=240
```

- `id`: 小节（二级章节）ID
- `user_subject`: 科目代码，如 240

响应中 `data.data.question` 为该小节下的题目列表，`data.data.chapter_section_num` 含 `chapter_num`、`section_num`。

## 四、策略逻辑

1. **有子节时**：遍历一级章节下的每个小节（`child`），对每个小节调用 `section-questions`，将题目写入 `ag_chapter_question`，`section_chapter_id` 直接为小节 ID。
2. **无子节时**：回退到原 assembly 流程（`has-progress` → `assembly` → `chapter/questions`），`section_chapter_id` 仍通过 `resolve_section_chapter_id` 推算。

## 五、跳过策略

- **小节抓取**：必须执行，每次同步都会对每个小节调用 `section-questions`，不跳过。
- **题目详情**：仅单个题目的 `get-question` 可跳过。若 `question_detail_exists` 为真，则跳过该题目的详情拉取。

## 六、影响

- 题目归属更精确，无需按题号区间推算
- 同步日志新增 `sync_type=section_questions`
- 无子节的一级章节回退到 assembly 流程
- 小节抓取不跳过，仅单个题目详情可跳过

## 七、使用方式

```bash
cd crawler
python3 sync_ruankao.py --config config.json
```

可选参数：`--sync-chapters`、`--skip-question-detail`、`--chapter-id`、`--force` 等保持不变。
