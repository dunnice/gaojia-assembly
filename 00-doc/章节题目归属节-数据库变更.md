# 章节题目归属节 - 数据库变更说明

## 一、变更背景

每道题目归属于「章」下的某一「节」。爬虫已增加 `section_chapter_id` 字段，用于记录题目归属的二级章节（节）ID。

## 二、表结构变更

### ag_chapter_question

新增字段：

| 列名 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| section_chapter_id | BIGINT NOT NULL | 0 | 归属的二级章节/节 ID，0 表示无子节或归属一级 |

## 三、执行 SQL（已有库需执行）

```sql
USE ruankao_gaojia;

-- 新增 section_chapter_id 列
ALTER TABLE ag_chapter_question
  ADD COLUMN section_chapter_id BIGINT NOT NULL DEFAULT 0
    COMMENT '归属的二级章节/节ID，0表示无子节或归属一级'
  AFTER chapter_id;

-- 可选：添加索引便于按节筛选
CREATE INDEX idx_section_chapter ON ag_chapter_question(section_chapter_id);
```

若列已存在则跳过；若报错 `Duplicate column name`，说明已执行过。

## 四、归属逻辑

- 一级章节（如「绪论」）下有多个二级章节/节（如「系统架构概述」「系统架构设计师概述」）
- 各节的 `all_question_num` 决定题目序号区间
- 例如：节 1 有 17 题 → 题号 1–17 归属节 1；节 2 有 6 题 → 题号 18–23 归属节 2
- 无子节时，`section_chapter_id` 等于一级 `chapter_id`

## 五、重新同步

执行迁移后，建议用 `--force` 重新同步以回填 `section_chapter_id`：

```bash
cd crawler
python3 sync_ruankao.py --config config.json --force
```

## 六、MySQL → SQLite 迁移

使用 `cmd/migrate` 从 MySQL 迁移到 SQLite 时，需先完成上述 ALTER TABLE，否则迁移会因缺少 `section_chapter_id` 列而失败。
